# 已知的坑

按踩到的频率排序。多数不是配置错，是插件与主题的既有行为。

## 1. `/es/` 全部 404

三种原因，按概率排：

- 固定链接重写规则没刷 → `wp rewrite flush --hard`
- 缓存/CDN 还存着旧响应 → 清页面缓存 + 清 CDN 该路径
- URL 模式还是「语言作为参数」→ 改成「目录名」并保存一次固定链接

## 2. 译文 slug 被加了后缀

期望 `/es/about/`，实际 `/es/about-2/`。

原因：Polylang 免费版不支持译文独立 slug，遇到同名冲突会加序号。多数情况是语言 URL 模式没设成目录，导致英文与西语在同一命名空间里抢 slug。

处置：先确认 URL 模式，再检查原 post 的 `post_name`。**不要手动删后缀**，删了会和英文页冲突。

## 3. 切换器点过去 404

只建了译文 post，没建语言关联。Polylang 靠 `pll_save_post_translations()` 建立映射，切换器按映射生成链接，没映射就等于没有这个版本。

```php
pll_save_post_translations(array_merge(
    pll_get_post_translations($original_id),
    [$lang => $new_id]
));
```

注意是全量数组，传单条会覆盖掉其他语言的关联。

## 4. hreflang 单向

英文页声明了西语，西语页没声明英文。Google 要求双向互指，单向声明会被忽略，等于白做。

检查方法：两边都抓一遍 `<head>`，交叉比对。

## 5. canonical 指回英文

译文页的 canonical 指向英文原页，等于告诉搜索引擎“这页是重复内容”，西语版不会被收录。

正确做法：`/es/about/` 的 canonical 指向 `/es/about/` 自己，语言之间用 hreflang 关联。

## 6. 主题把链接写死成绝对地址

```php
<a href="<?php echo home_url('/shop/'); ?>">   // 西语页上也指向英文 /shop/
```

正确写法 `pll_home_url()` 或 `get_permalink(pll_get_post($id))`。改子主题，不要把父主题里的 `home_url` 全局替换——会连带改坏后台链接。

## 7. WooCommerce 半翻

能翻商品标题描述，但加购按钮、购物车、结账、邮件还是英文。

原因：界面文案随 locale 加载 WooCommerce 官方语言包，但端点 slug、邮件模板、库存同步属于付费集成。免费方案无法完整覆盖。

处置：如实报缺口。要么买 add-on，要么在验收报告里明确标注“购物流程未翻译”，不要默认它好了。

## 8. 邮件模板没翻

客户收到英文订单邮件，前面的页面翻译全白做。订单邮件独立于页面，验收必须单独测一封。

## 9. 归档页掉回英文

翻了 post 没翻 term。分类、标签、商品分类各自是独立对象，归档页标题与描述来自 term。

## 10. 菜单跟着语言走，但只建了一套

Polylang 默认把菜单绑定到语言。只建一套英文菜单，西语页会显示英文菜单，或者干脆空白。

处置：每种语言建一套菜单，或使用「同步菜单」功能后逐项替换文案。

## 11. 构建器内容一改就坏

正则替换 `_elementor_data` 或 Gutenberg 的块注释，导致编辑器报“区块包含意外内容”。

处置：JSON 解析后按节点改，`serialize_blocks()` 序列化。破坏后恢复成本很高，动手前先备份这几条 meta。

## 12. 媒体 alt 翻译破坏“媒体不变”

翻 alt 要改附件记录，与约束冲突。

处置：默认不动附件。确实需要多语言 alt 时，用页面级 override（区块属性或 SEO 插件字段），不改附件本身。

## 13. 日期与数字被“翻译”

把 `March 5, 2026` 换成 `5 de marzo de 2026` 是对的，但那是 locale 格式化的结果，不是字符串翻译。硬翻格式串会在换语言时炸掉。

处置：日期交给 `date_i18n()`，数字交给 `number_format_i18n()`，价格交给 Woo 的货币接口。只翻标签，不翻格式。

## 14. RTL 语言布局崩

阿拉伯语、希伯来语需要 `dir="rtl"`。多数主题只写了 LTR 样式，加 RTL 后导航与表格错位。

处置：加 RTL 前先确认主题支持，或单独排期。不要顺手加进 10 语言默认集。

## 15. 两套多语言插件并存

旧 TranslatePress 的表还在，新装的 Polylang 语言判定错乱，表现为页面语言随机、切换器乱跳。

处置：卸载旧插件 → 删 `wp_trp_*` 表 → 清对象缓存 → 再装新的。顺序错了会残留。

## 16. 站点是多站点网络

多语言插件在多站点下的行为与单站不同：语言按子站隔离，切换器不跨站。动手前先确认是不是多站点（`wp site list`），是的话方案要重写。

## 17. 法律页机器翻译

隐私政策、条款、退款政策直接机翻有合规风险。这类页面标注「需人工/法务复核」，不要计入“已完成”。
